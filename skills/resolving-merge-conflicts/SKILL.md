---
name: resolving-merge-conflicts
description: "進行中のgitマージ/リベースのコンフリクトを解消する必要があるときに使う。"
---

1. **マージ/リベースの現在の状態を確認する。** git の履歴と、コンフリクトが発生しているファイルを確認する。

2. **各コンフリクトの一次情報源を探す。** それぞれの変更がなぜ行われたのか、元の意図は何だったのかを深く理解する。コミットメッセージを読み、PRを確認し、元のissue/チケットを確認する。

3. **各ハンクを解消する。** 可能な限り両方の意図を保持する。両立できない場合は、マージが目指しているゴールに合致する方を選び、トレードオフを書き留める。**新しい振る舞いを勝手に作り出さない。** 必ず解消する。`--abort` は使わない。

4. プロジェクトの**自動チェック**（通常は型チェック → テスト → フォーマットの順）を見つけて実行する。マージによって壊れたものを修正する。

5. **マージ/リベースを完了させる。** すべてをステージしてコミットする。リベース中であれば、すべてのコミットがリベースし終わるまでリベース処理を続行する。
