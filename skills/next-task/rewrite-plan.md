# 書き直しから委譲する

手順5で「書き直しから委譲する」に当たったときの依頼文と、メインが `## やること` を書いてよいときの条件。

## 書き直しから委譲する

   **書き直しから委譲する**: 下の共通の依頼文と手順5cの依頼文に、次を足して渡す。文書の担当は
   並べて起こさない（メインが `## やること` を読む前に動き出すため。1匹で通す）。手順5cの
   「文書の担当が完了した」を待つ項目も渡さない:
   - 「**先に `tw edit T-xxx --section 'やること' --body-file -` で `## やること` を書き、作業せずに返す**
     （節の中身だけを渡し、`## やること` の見出しの行は付けない。`### 1. …` の形で `### 1.` から穴なく
     実行の順に番号を振った段で書き（形が違えば `tw edit` が終了コード2で拒む）、完了条件の各行を
     どの段のどのファイルのどこをどう直して満たすかまで書く。段は1回の返却で済ませる大きさにする。
     並べて走らせてよい段は段の欄を書く（正典「タスクファイル」の「段の形」）。
     描画を変えるタスクでは、組み立てた直後に画を撮ってメインの目視を受ける段を、E2E の期待値を
     撮り直す段と `tw verify` の段より前に置く。
     作業ツリーが変わったあとの初回の記入は `WORK_BEFORE_PLAN` で拒まれるので、読むだけの調べを
     先に済ませてから書く）。返却の1行目は `計画 0/<段の数> | <計画の要点を1文>`。そのあとはメインが
     `SendMessage` で渡す段を1つずつ、`## やること` のとおり実装する。判断が想定より要ると
     分かったら押し切らず、そこで止めて報告する。`## 目的・背景`・`## 完了条件` は変えない
     （変えると `FRAME_CHANGED` で拒まれる。`--change-frame` は付けず、変えたい理由を報告する）」

## メインが書いてよいとき

   **メインが書いてよいとき**: 「書き直しから委譲する」に当たり、同じセッションでこのタスクの設計を
   利用者と決めていて、`## やること` に要る正典・コードをメインがすでに読んでいるときだけ、
   メインが自分で `## やること` を書く（メインが新たに読み込みに行くなら委譲する。メインの文脈を
   膨らませない）。書いたら中身だけを `tw edit T-xxx --section 'やること' --body-file -` で渡し、
   `tw plan-check T-xxx` が `PLAN_FIRST` を返し、`## やること` が `## 完了条件` の各行を覆っているかを
   確かめる（足りなければ自分で `tw edit` を書き直す）。確かめたら「計画どおりに委譲する」。
