# 文書の担当を並べて起こす

手順5の「計画どおりに委譲する」で、実装の担当と同時に文書の直し専用の担当を起こすときの条件と依頼文。

   **文書の担当を並べて起こすとき**（手順5の「計画どおりに委譲する」だけ）: `## やること` に文書の直し先と中身（ファイルパスと直す内容）が
   書いてあり、`dispatching-parallel-agents` スキルの独立の判定で実装の担当と独立と言えるときだけ、実装の委譲と同時に、文書の直し
   専用の Agent を1体、`sonnet` 固定で並べて起こす（同時に足すのは1匹まで。実装の担当と合わせて2匹）。
   独立でなければ並べず、これまでどおり1匹にまとめる。`subagent_type` の選び方は
   実装の担当と同じ（一覧に末尾が `no-delegate` の行があればその名前、無ければ `general-purpose`）。

   本文は貼らず、タスクIDと `## やること` に書かれた文書のパスを渡し、次を渡す:
   - 「`## やること` に書かれた文書だけを直す。触ってよいファイルはそれだけで、実装のファイル・
     `develop/`・グローバル設定・ホームのファイルには触らない」
   - 「走らせてよいコマンドは文書の検査（そのプロジェクトの迷子の参照の検査・整形）だけ。
     build・E2E・check 全段のような重いコマンドは走らせない。検証コマンドは実装の担当の
     `tw verify` の1回に寄せるので、ここでは打たない」
   - 「`tw` コマンドは `tw show T-xxx` だけ（`tw edit`・`tw verify` など他は打たない）」
   - 「コミットしない（`git add -A` もしない。着手の印が立った作業ツリーでコミットしようとすると拒まれる。
     拒まれたら回避せず、コミットせずに報告で返す）。`git stash` を使わない」
   - グローバルへのリンク・ホームのファイルを触らない、外部に捨てる資源を作らない、`/` やホーム
     全体を `find` で探さない、待つコマンドに上限を付ける、背景で起こしたコマンドは報告の前に
     止める、を渡す（実装の担当と同じ諸注意）
   - `general-purpose` に委譲したときだけ渡す: 「サブエージェントの中では別のエージェントを立てない」

   文書の担当の完了（hand-back か、Agent ツールの完了の通知。届いたと見なす基準は手順5bと同じ）が
   届いたら、その差分に目を通してから、実装の担当へ `SendMessage` で「文書の担当が完了した」と
   伝える。文書の担当の差分も、実装の担当の差分と合わせて手順6でメインが読む。
