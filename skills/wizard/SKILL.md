# ウィザード

**ウィザード**とは、手でやると面倒で、毎回 AI に説明し直すのも面倒な手作業の手順を、人間に1歩ずつ案内する bash スクリプトである。各 URL を開き、何をクリックして何をコピーするかを正確に伝え、値を受け取り、置くべき場所(`.env`、GitHub のシークレット)に書き込み、各段階で確認を取り、残りの段階数を示す。外部サービスの設定でも、一度きりの移行でも、プロジェクトをある状態から別の状態へ移すものでもよい。

気持ちよい操作感は [template.sh](template.sh) で既に解決済み: 段階ごとの進捗、確認の関門、OS をまたぐ URL の起動(WSL を含む)、隠した入力でのシークレットの受け取り、冪等な `.env` の upsert、`gh secret` / `gh variable` への書き込み、締めのまとめ。**あなたの仕事は、手順の範囲を決めて段階を書くことだけである。** `STAGES` の目印より上にあるライブラリ部分はどのウィザードでも同一で、その一貫性が要点なので、決して手で書き換えない。

ウィザードは既定では使い捨て: 1回の実行のために作り、スクラッチか `scripts/` 配下に保存し、作業が終わったら削除する。リポジトリに置いておきたい繰り返し使えるセットアップ手順をユーザーが望むときだけ、コミットする。

## 手順

### 1. 手順の範囲を決める

人間が踏むべき手作業のステップと、その途中で受け取る値をすべて洗い出す。いきなり尋ねず、先にリポジトリを読む:

- セットアップなら: `.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、フレームワークの設定、`.github/workflows/*`(`secrets.*` / `vars.*` の参照はすべて、ウィザードが用意すべき値)。
- 移行や状態の移行なら: 現在の状態、目標の状態、その間にある取り消せない操作。

そのうえで、段階の順序つきの一覧と、各段階が生む値をユーザーに見せて確認する。ユーザーは足しても、削っても、並べ替えてもよい。

**完了の条件:** すべての段階に順に名前が付き、受け取る値それぞれについて (a) 人間がどこで入手するか、(b) どこに書くか(`.env`、GitHub のシークレット、両方、どこにも書かない。純粋な操作だけの段階もある)、(c) 秘密か(隠した入力)公開か、が分かっている。

### 2. 各段階の道筋を描く

各段階について、人間がたどる正確な道筋を書く: どの URL を開くか、そこで何をするか、値がどこに表示されるか、どの変数を埋めるか。例: 「ダッシュボード → Developers → API keys → Reveal test key → コピー」。現在の UI や正確なコマンドを実際には知らないなら、そう言ってユーザーに尋ねるかドキュメントを調べる。存在しないかもしれない手順を創作しない。

**完了の条件:** すべての段階が、見知らぬ人でも従える具体的な指示にたどれる。

### 3. ウィザードを書く

`template.sh` を目的のパスにコピーする。例の段階を、依存関係の順に、ステップごとの `stage` 1つに置き換える。ライブラリの補助関数を使う: `stage`、`say` / `step`、`open_url`、`ask` / `ask_secret`、`write_env`、`set_secret` / `set_var`、`pause` / `confirm`。`TOTAL_STAGES` を、書いた段階の数に合わせる。

雛形が掲げる水準を守る: 値を尋ねる前にその URL を開く、秘密のものには `ask_secret` を使う、保持する値はすべて `write_env` する、CI が実際に必要とする値にだけ `set_secret` する、取り消せない操作の前には必ず `confirm` する。各 `stage` は画面を消去して現在のステップだけが見えるようにするので、人間が必要とするものがスクロールで流れないよう、1つの段階は1つの焦点を絞った作業にする。目印より上のライブラリには手を触れない。

### 4. 検証して手渡す

- `bash -n <script>`。`shellcheck` があれば実行する。
- `chmod +x <script>`。
- 自分で最後まで実行しない: ブラウザを開き、人間の入力で止まる。代わりに静的にたどる: 手順1の値がすべて受け取られ、手順1で言った場所に書かれ、`set_secret` の名前が CI の `secrets.*` の参照と一字一句一致している。
- 実行のしかたをユーザーに伝える。繰り返し使えるセットアップ手順なら、コミットして README からリンクし、次の人が AI に尋ねずにスクリプトを実行できるようにする。
