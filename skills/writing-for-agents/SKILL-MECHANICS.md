# スキルの仕組み

[`writing-for-agents`](SKILL.md) のうち、スキルに固有の分岐: 文書がスキルのときに変わること
（frontmatter、起こし方の選択、ルーターのスキル）。それ以外の書き方はすべて `SKILL.md` の共通の参照に従う。

## 起こし方

選択は2つで、2つの負荷を取り替える:

- **モデルが起こす**スキルは `description` を持つので、エージェントが自分で起こせ、他のスキルからも
  辿れる。名前を打って呼ぶこともできる: モデルが起こせるスキルは常に人からも届き、description は
  エージェントの発見を*足す*だけで、人の届く道を取り去ることはない。description はスキルの一番上の
  文脈のポインタで、常に読み込まれたままになる: 見つけてもらえることと引き換えの、恒久的な文脈の負荷だ。
  中身が全部参照のモデルが起こすスキルは、共有の参照の置き場にもなる: 別のスキルがそれを起こせるので、
  いくつものスキルが要る参照を1か所に置ける。仕組み: `disable-model-invocation` を書かず、トリガーの
  分岐を運ぶモデル向けの description を書く（`SKILL.md` のポインタの書き方がそのまま効く）。
- **人が起こす**スキルは description をエージェントの手から外す: 名前を打った人だけが起こせ、他の
  スキルからは起こせない。文脈の負荷はゼロだが、認知の負荷を使う: それがあることを覚えておく索引は
  人だ。仕組み: `disable-model-invocation: true` を書く。`description` は人向けになり、1行の要約にして
  トリガーの並びを外す。

モデルが起こす形を選ぶのは、エージェントが自分で辿り着く必要があるとき、または別のスキルが辿り着く
必要があるときだけ。手でしか起こさないなら、人が起こす形にして文脈の負荷を払わない。

2つの人が起こすスキルがどちらも要る共有の参照は、どちらにも置けない: description が無いので、互いに
起こせない。スキルの仕組みの外の素のファイルへ押し出し、どのスキルからも指せる外の参照にする。

## 起こし方で分ける

分け方のうち起こし方の切れ目（順序の切れ目は `SKILL.md`）: 独立して起こすべき別の先導語（実際に
プロンプトで使うトリガーの語）があるとき、または別のスキルが辿り着く必要があるときに、モデルが起こす
スキルを分ける。新しく常に読み込まれる description の文脈の負荷を払うので、独立して届くことにそれだけの
値打ちが要る。

## ルーターのスキル

人が起こすスキルが覚えきれないほど増えたら、積もった認知の負荷は**ルーターのスキル**で治す: ほかの
スキルの名前と、それぞれいつ手を伸ばすかを並べた、人が起こすスキル1つ。人が覚えるのはそれ1つで済む。
できるのは示すことだけで、起こすことはできない: 人が起こすスキルには description が無いので、人の
ほかは誰も辿り着けない。
