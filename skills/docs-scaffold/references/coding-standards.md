# coding-standards の型

`docs/coding-standards.md`（コーディング規約の理由と例外）の雛形。`docs/coding-standards.md` が索引と結論、`docs/coding-standards/` が詳細の一組になる。`<...>` の所を、対象のプロジェクトの言葉で埋める。

## 規則そのものと理由の分担

- **規則そのものは `.claude/rules/` が正典**。触るファイルに合うものが自動で届く短い箇条書きで、ここには書き写さない
- **この文書には、規則の理由と例外だけを書く**。規則の本文を二重に書かない
- lint・テストが機械で検査する規則は `.claude/rules/` に一覧の行を置かず、この文書だけに書く（検査が守るので、毎回の手の動きに載せなくてよい）
- `.claude/rules/` を使っていないプロジェクトでは、規則の置き場（`AGENTS.md`・`CLAUDE.md` など）を冒頭の1段落で名指す

## 一組の形

- `docs/coding-standards.md`: 冒頭の説明、3行、読み方、節の索引を持つ
- `docs/coding-standards/<種類>.md`: 規則の種類（型・テスト・コメント・UI など）ごとの理由と例外
- 最初は `coding-standards.md` 1枚で書く。**30KB を超えたら**、節を `docs/coding-standards/` へ分ける（分け方は下の「X/ に分ける基準」）

## coding-standards.md の雛形

````markdown
# コーディング規約の詳細

コードの書き方の規則の一覧は `<規則の置き場。例: .claude/rules/>` にある。**ここにはその理由と例外**
だけを書く（規則本体は置き場側が正典で、二重に書かない）。

配置・分割の規約は `docs/architecture.md` が正典。

責務: 規約の理由と例外を持つ（規約そのものは `<規則の置き場>` が正典で二重に書かない）。
読む時: 規約の理由と例外を確かめたいとき。
直す時: 規約の理由・例外を変えたとき、lint やテストが検査する規則を追加・変更したとき。

## このファイルの読み方

現時点では小さいので通読してよい。**30KBを超えたら**、下の索引で節を1つ特定して、
その節だけを次の形で読む運用に切り替える:

```bash
# `##` の節を丸ごと（配下の `###` も含めて）読む
sed -n '/^## <節の名前>/,/^## /p' docs/coding-standards/<種類>.md

# `###` の小節だけを読む
sed -n '/^### <小節の名前>/,/^#\{2,4\} /p' docs/coding-standards/<種類>.md
```

### 節の索引

**索引の行は本文の `##` / `###` の節と1対1**。`grep -c '^#\{2,3\} ' docs/coding-standards.md` と行数が合う。
30KB を超えて分けたら、列に「子のファイル」を足す。

| 節                      | 中身                      |
| ----------------------- | ------------------------- |
| ## <規則の種類1>        | <その節の理由・例外の要旨> |
| ## <規則の種類2>        | <その節の理由・例外の要旨> |

## <規則の種類1>

### <規則の名前>

理由: <なぜこの規則か>
例外: <守らなくてよい場面>
````

規則の種類は、そのプロジェクトで実際に規則がある所だけ節にする（例: 型、テスト、コメント、UI、会話内容などの取り扱い）。空の節を先回りして置かない。

## 節ごとに書くこと

- 規則ごとに「理由」と「例外」を書く。理由が書けない規則は、規則の置き場から外す候補
- lint・テストが検査している規則には、検査の場所（設定ファイルやテストのパス）を1行添える
- 最優先の規約（例: 機密・個人情報の扱い）があれば、節の頭に「他のどの規約よりも優先する」と書く

## X/ に分ける基準

- `coding-standards.md` が30KB を超えたら分ける
- 分けるときは規則の種類（`##` の節）を単位にし、1つの種類を1つの子のファイルにする。1つの節を複数のファイルにまたがらせない
- 親には、読み方と節の索引（節／子のファイル）を残し、本文は子へ移す
- 子のファイルは冒頭に自分の節の索引を持つ。索引で節を1つ特定し、`sed -n` で節だけを読む
- 分けたあと、索引の行は本文の節と1対1のまま保つ
