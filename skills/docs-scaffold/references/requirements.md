# requirements の型

`docs/requirements.md`（要件定義）の雛形。`docs/requirements.md` が索引と結論、`docs/requirements/` が詳細の一組になる。`<...>` の所を、対象のプロジェクトの言葉で埋める。

## 一組の形

- `docs/requirements.md`: 冒頭の3行、節の索引、結論だけの節（目的・スコープ・技術制約・未決事項）を持つ
- `docs/requirements/<節の名前>.md`: 節が長くなったときの本文。子のファイルは冒頭に自分の節の索引を持つ
- 最初は `requirements.md` 1枚で書く。**30KB を超えたら**、節の本文を `docs/requirements/` へ分ける（分け方は下の「X/ に分ける基準」）

## requirements.md の雛形

````markdown
# <プロジェクト名> 要件定義

最終更新: <YYYY-MM-DD>
ステータス: <ドラフト／確定>（未決事項は「7. 未決事項」）

責務: やること・やらないこと・技術制約・未決事項を定める要件定義。
読む時: 要件・やらないこと・技術制約・未決事項を知りたいとき。
直す時: 要件を追加・変更したとき、未決事項を解決したとき。

## このドキュメントの読み方

現時点では小さいので通読してよい。**30KB を超えたら**、下の索引で節を1つ特定して、
その節だけを読む運用に切り替える（節を `docs/requirements/` へ分ける）。

### 節の索引

**索引の行は本文の `##` / `###` の節と1対1**（節を足したり消したりしたら、ここも同じ数だけ動かす。
`grep -c '^#\{2,3\} ' docs/requirements.md` と行数が合う）。

| 節                           | 中身                                             |
| ---------------------------- | ------------------------------------------------ |
| ## 1. 概要・目的             | 何のために作るのか。目的と手段の区別             |
| ## 2. スコープ               | やること・やらないこと・想定利用者               |
| ### 2.1 対象とすること       | やること                                         |
| ### 2.2 対象外とすること     | やらないこと。機能を足す前にここを見る           |
| ### 2.3 想定利用者           | 誰が使うか                                       |
| ## 3. 技術制約               | 設計を縛る制約と、その理由                       |
| ## 4. 機能要件               | 機能ごとの要件                                   |
| ## 5. 実行環境・非機能要件   | 動かす環境と、性能・安全などの要件               |
| ## 6. 既存のものとの関係     | 既存の道具との違い。なぜ作るのか                 |
| ## 7. 未決事項               | まだ決めていないこと                             |
| ## 8. 参照                   | 関連する文書・外部の資料                         |

## 1. 概要・目的

<何のために作るのか。目的と、それを実現する手段を分けて書く>

## 2. スコープ

### 2.1 対象とすること

### 2.2 対象外とすること

### 2.3 想定利用者

## 3. 技術制約

## 4. 機能要件

## 5. 実行環境・非機能要件

## 6. 既存のものとの関係

## 7. 未決事項

## 8. 参照
````

見出しの番号と名前は、そのプロジェクトで要らない節を削ってよい。削ったら索引の行も削り、行数と見出し数を合わせる。

## 節ごとに書くこと

- 1. 概要・目的: 目的と手段を区別する。機能を足す前に見る節
- 2.2 対象外とすること: 機能を足そうとする前に見る節。やらないことと、その理由を1行ずつ
- 3. 技術制約: 設計を疑う前に読む。制約の理由と、外れたときに何が起きるか
- 7. 未決事項: 解決したら本文の該当節へ移して、ここから消す

## X/ に分ける基準

- `requirements.md` が30KB を超えたら分ける
- 分けるときは `##` の節を単位にする。1つの子のファイルに複数の節を入れてよいが、1つの節を複数のファイルにまたがらせない
- 親の `requirements.md` には、見出しと索引の表（列は 節／中身）だけを残し、索引の下に節から子のファイルへの一覧を置く
- 子のファイルは冒頭に自分の節の索引を持つ。親から本文を切り出すのではなく、索引で節を特定して子のファイルだけを開く
- 分けたあと、索引の行は本文の節と1対1のまま保つ
