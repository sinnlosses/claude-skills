## 目的

タスク運用の設定の置き場が `CLAUDE.md` 固定なのをやめ、`AGENTS.md` を使う環境でも設定が読めるように
する。あわせて4箇所に散っている読み取りを1つの関数に寄せる。

## 完了条件

- `## タスク運用` 節を持つファイルを `AGENTS.md` → `CLAUDE.md` の順で探し、**最初に見つかったものを
  設定とする**関数が1つあり、次の4箇所がそれを使う:
  `task.py` の `read_branch_setting`、`ship.py` の `read_verify_command`、`init.py` の
  `check_claude_md`、`skills/maintenance-docs/scripts/check_docs.py` の「## タスク運用」節の検査
- **両方のファイルに `## タスク運用` 節があれば `INVALID`（終了コード3）**。どちらに従うか機械が
  決められないため、黙って片方を選ばない
- `AGENTS.md` も `CLAUDE.md` も無い／節が無いときの扱いは従来と同じ（`init.py` は `MISSING`、
  `task.py` の `read_branch_setting` は `既定`）
- `selftest.py` または `selftest_task.py` に、`AGENTS.md` だけのリポジトリ・両方あるリポジトリの
  2ケースがある
- `./check.sh` が通る

## 背景

設定の3行（`- 検証コマンド:`・`- 整形コマンド:`・`- ブランチ:`）を読むのは4箇所で、すべて
`CLAUDE.md` 決め打ち:

- `skills/task-workflow/scripts/task.py:184` `read_branch_setting`
  （`os.path.join(toplevel, "CLAUDE.md")` を開き、`^- ブランチ:` の先頭語だけを読む）
- `skills/task-workflow/scripts/ship.py:35` `read_verify_command`（`^- 検証コマンド:` の最初の `` `…` ``）
- `skills/task-workflow/scripts/init.py:68` `check_claude_md`（節と3行の在否、`- ブランチ:` の語彙）
- `skills/maintenance-docs/scripts/check_docs.py:28` の `TASK_SECTION_KEYS` を使う検査8

T-013 で `- 主ブランチ:` 行（任意）が増えるので、そちらもこの関数経由で読む。
適用中の5リポジトリに `AGENTS.md` を置いているものは1つも無いため、既存の挙動は変わらないことが期待値。

## 注意

- `skills/maintenance-docs/scripts/check_docs.py` は `CLAUDE.md` を**ドキュメントとしても**見ている
  （索引の対象外、見出しの重複、参照先の実在）。設定の置き場としての探索を足すだけにして、
  ドキュメントとしての扱いは変えない
- 正典 `WORKFLOW.md`「ファイル配置と CLAUDE.md」の節名・見出しの表記を、探索順が分かるように直す
  （節の3行の形は変えない）
