## 目的

タスク運用の設定の置き場が `CLAUDE.md` 固定なのをやめ、`AGENTS.md` を使う環境でも設定が読めるように
する。あわせて4箇所に散っている読み取りを1つの関数に寄せる。

## 完了条件

- `## タスク運用` 節を持つファイルを `AGENTS.md` → `CLAUDE.md` の順で探し、**最初に見つかったものを
  設定とする**関数が1つあり、次の4箇所がそれを使う:
  `task.py` の `read_branch_setting`、`ship.py` の `read_verify_command`、`init.py` の
  `check_claude_md`、`skills/maintenance-docs/scripts/check_docs.py` の「## タスク運用」節の検査
- **両方のファイルに `## タスク運用` 節があれば `INVALID`（終了コード3）**。どちらに従うか機械が
  決められないため、黙って片方を選ばない
- `AGENTS.md` も `CLAUDE.md` も無い／節が無いときの扱いは従来と同じ（`init.py` は `MISSING`、
  `task.py` の `read_branch_setting` は `既定`）
- `selftest.py` または `selftest_task.py` に、`AGENTS.md` だけのリポジトリ・両方あるリポジトリの
  2ケースがある
- `./check.sh` が通る

`CLAUDE.md` 決め打ち:

  （`os.path.join(toplevel, "CLAUDE.md")` を開き、`^- ブランチ:` の先頭語だけを読む）
- `skills/task-workflow/scripts/ship.py:35` `read_verify_command`（`^- 検証コマンド:` の最初の `` `…` ``）
- `skills/task-workflow/scripts/init.py:68` `check_claude_md`（節と3行の在否、`- ブランチ:` の語彙）
- `skills/maintenance-docs/scripts/check_docs.py:28` の `TASK_SECTION_KEYS` を使う検査8

T-013 で `- 主ブランチ:` 行（任意）が増えるので、そちらもこの関数経由で読む。
適用中の5リポジトリに `AGENTS.md` を置いているものは1つも無いため、既存の挙動は変わらないことが期待値。

## やること

いまのコードで前提を調べ直した結果、背景に書いた4箇所の直書き（行番号は前後しているが対象は
実測どおり）と、T-018 で新設された `layout.py`（置き場の1箇所化。`check_repo.py` の
`check_task_workflow_layout` が直書きを AST で検出する）は崩れておらず、前提はそのまま成立する。
`- 主ブランチ:` を読む `ledger._configured_base_branch`（T-013）も同じく `CLAUDE.md` 決め打ちで、
背景が言う「そちらもこの関数経由で読む」対象として実装に含める。

- `skills/task-workflow/scripts/layout.py` に置き場を1つ足す: `CONFIG_FILENAMES = ("AGENTS.md",
  "CLAUDE.md")`・`TASK_SECTION_HEADING = "## タスク運用"`・例外 `ConfigConflict`・関数
  `find_config_file(root) -> tuple[str, str] | None`（この順で探し、節を持つ最初のファイルの
  `(パス, 中身)` を返す。両方に節があれば `ConfigConflict`。どちらにも節が無ければ `None`。
  パスは `os.path.normpath` で `./` を落とし、既存の `"OK\tCLAUDE.md"` 系の出力形を変えない）
- `task.py` の `read_branch_setting` と `ship.py` の `read_verify_command`（`ship.py` に
  `import layout` を足す）を `layout.find_config_file` 経由に直す。`None` のときの既定
  （`既定`／打たない）は変えない。`task.py` の `main()` の `except ledger.NoBaseBranch as e:` に
  `layout.ConfigConflict` を足して同じ `INVALID`・終了コード3にする（`ship.read_verify_command` は
  `cmd_ship` 経由で同じ except に乗る）
- `ledger.py` に `import layout` を足し、`_configured_base_branch`（T-013）も
  `layout.find_config_file` 経由に直す（`base_branch()` 経由で `task.py` のほぼ全サブコマンドが
  通るので、これも同じ `except` で `INVALID` になる）
- `init.py` の `check_claude_md`: 引数を無くして `layout.find_config_file(".")` を使う形に直し、
  `CLAUDE_SECTION` の直書きを `layout.TASK_SECTION_HEADING` に差し替える。**`MISSING` と
  `NO_SECTION` の区別は残す**（前者はどちらのファイルも無いとき、後者は在るのに節が無いとき——
  `layout.CONFIG_FILENAMES` の順で実在する最初のファイル名を出す）。`ConfigConflict` は
  `INVALID\t...` を返す（他の返り値と同じ「印字するだけ」の形。`init.py` はここで `SystemExit` しない）
- `skills/maintenance-docs/scripts/check_docs.py`: `retrospect/scripts/material.py` と同じ

  `layout.find_config_file(root)` の結果から節を読むように直す（`ConfigConflict` は検査5の
  確定群に1件積む）。**CLAUDE.md をドキュメントとして見る他の検査（4・8・10 の `claude_body`）は
