## 目的

主ブランチ名が `main` に固定されているのをやめ、`master`・`trunk` のリポジトリでも
`task` コマンドが動くようにする。

## 完了条件

- `skills/task-workflow/scripts/ledger.py` に `base_branch(cwd)` があり、`task.py`・`ship.py` が
  git に渡す枝名をすべてそれ経由で得ている
- `grep -nE '"main"|main\.\.HEAD|refs/heads/main' skills/task-workflow/scripts/task.py skills/task-workflow/scripts/ship.py`
  が、コード（git の引数・比較）としては0件（コメント・docstring の説明文は対象外）
- `selftest_task.py` の足場が枝名を引数で受け、**主ブランチが `master` のリポジトリで一式を
  通すケースが1本ある**（足場が `main` のままなら汎用化できたことにならない）
- `./check.sh` が通る

## 背景

git に渡す引数としての `main` は `skills/task-workflow/scripts/task.py` に15行、`ship.py` に5行、
`selftest_task.py` の足場に13行ある。

- `task.py:65` `ls-tree --name-only -r main -- develop/task`、`:72` `show main:develop/task/<file>`、
  `:77` `show main:docs/history/tasks.md`
- `task.py:388-393` `claim` の追い付き（`branch != "main"`・`rev-list --count main..HEAD`・
  `merge --ff-only main`）、`:426` `checkout -b feature/T-xxx main`
- `task.py:518-592` `ship` の後始末（`branch == "main"`・`rev-parse main` を2回・降りる先の
  `targets` に `"main"`・`checkout -q --detach main`）
- `ship.py:57` `find_main_worktree`（`w.branch == "main"`）、`:79` `merge-base --is-ancestor main HEAD`、
  `:81` `rebase main`、`:108-109` `rev-parse main` と `update-ref refs/heads/main`

`ledger.py` には `current_branch`・`git_toplevel`・`list_worktrees` と git を叩く関数が揃っているので、
枝名を決める関数もここに置く。

適用中の5リポジトリ（claude-skills・tsukumo・Git-Bulk-Maestro・gitlab-watari-dori・helm-yadokari）は
**すべて主ブランチが `main`**。よって既存リポジトリの挙動は変わらないことが期待値で、変わったら
それは不具合。

## 決まっていること（蒸し返さない）

決め方の順はこれにする:

1. 設定ファイルの `- 主ブランチ:` 行があればそれ（**任意行**。保護ブランチや複数リモートの逃げ道）
2. `git symbolic-ref --short refs/remotes/origin/HEAD` の枝名
3. `main`・`master`・`trunk` のうち `git rev-parse --verify` で**実在する**もの
4. どれも無ければ `INVALID`（終了コード3）。**黙って `main` を作らない**

## 解くべき論点

- `ship.py:108-109` の `update-ref refs/heads/main <head> <seen_main>`（見たときから動いていたら
  失敗する比較付き更新）を枝名可変にしたとき、他の作業ツリーとの競合検知が変わらないか
- `find_main_worktree` の名前と、`task.py:582` の降りる先の決め方（`back` → 主ブランチ →
  detached）を枝名可変にしたときの表記
- `base_branch()` を毎回 git に問い合わせるか、1プロセスで1回だけ求めて覚えるか
  （`task status` は1回の実行で何度も枝名を要る）
- 順2で `origin` が無く別名のリモート（`upstream` など）しか無いリポジトリのとき、順3へ落ちるか、
  そのリモートの HEAD を見るか

## 注意

- `- 主ブランチ:` 行は**任意**。無いのが既定で、3行（検証コマンド・整形コマンド・ブランチ）の
  「行を消さない」規約には**入れない**（`MISSING_LINE` にしない）
- 正典 `skills/task-workflow/WORKFLOW.md` の「送り出し」「`task` コマンドの参照」にある `main` の
  記述は、枝名が可変になったことが分かる書き方に直す（既定が主ブランチであることは変えない）
- 調べて順1〜4のどれかが成り立たないと分かったら、`## 解くべき論点` に足して設計を変えてよい
