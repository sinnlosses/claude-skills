## 目的・背景
いまの `/next-task` は `loopable: Y` なら色1つの変更でも、計画・委譲・検証・受け入れのレビュー・振り返り・送り出しを全部通り、中身の作業より段の出入りのほうが長い（利用者の指示）。基準に当たるタスクはメインが自分で直し、検証と送り出しだけを通す「委譲しない近道」を作る。基準そのものは、T-043・T-044 の段ごとの所要時間の記録を見て見直せる形にする。

いま: `skills/task-workflow/WORKFLOW.md` の「difficulty とモデルの切り替え」は「一致していても委譲する——理由はモデルではなく文脈の隔離」「委譲しないのは `loopable: N` に当たるときだけ」「`haiku` を例外にしないのは…『これは例外か』の判断が毎回1つ増えるため」と書く。近道はこの方針を変える。`skills/next-task/SKILL.md` で委譲しない道は `loopable: N` の `main-run.md` だけ。タスクの front matter（`skills/task-workflow/scripts/taskfile.py`）と `tw new` の引数（`skills/task-workflow/scripts/task.py` の `p_new`）に近道の印は無い。

## 決まっていること（蒸し返さない）
- 近道に当たるかは**登録時に `/plan-tasks` が決めて印を付け**、`tw` が機械で測れる条件を検査する。`/next-task` は印を見るだけで、着手時に「これは近道か」を判断しない（利用者が選んだ。正典が挙げた「判断が毎回1つ増える」を避けるため）
- 登録時に人（`/plan-tasks`）が見る条件: 振る舞いの契約（公開の出力・引数・終了コード・正典の規則）を変えない。`tw` が機械で見る条件: `difficulty` が `haiku`、`## やること` の段が1つ、`### 名指すファイル` が少ない（数のしきい値は論点）
- 近道で通すのは、`## やること` に沿ったメインの直し・`tw verify`・`tw done`・コミット・`tw ship`。委譲・受け入れのレビュー・振り返り（手順6a）は通らない
- 基準の値（しきい値）は正典の1か所（WORKFLOW.md の表）とそれを読むコードの定数にだけ置き、週ごとの振り返りが `tw metrics --stages` の近道と通常の比較から見直せるようにする
- 近道で進めたタスクは flow の記録で通常と見分けられる

## 解くべき論点
- 印の持ち方: front matter の欄（例 `direct: Y`）か別の形か。`tw new`・`tw edit`・`tw adopt` の引数、Beads 方式での置き場（`skills/task-workflow/scripts/beads.py` の `to_task` が読める形）
- `tw` の機械検査をどこで掛けるか: 登録時（`tw new` が条件を外れた印を終了コード2で拒む）だけか、着手時（`tw claim` か `tw plan-check` の出力に近道かを出す）にも掛けるか。登録のあとに `tw edit` で段や `difficulty` が変わったときの扱い
- `### 名指すファイル` の数のしきい値と、「差分が数行」をどう扱うか（直したあとの差分が大きくなったら近道を降りて通常の委譲に戻すか、記録だけ残すか）
- flow で近道を見分ける形（`claim` に欄を足すか、T-043 の `lap` に段を足すか）と、`tw metrics --stages` で近道と通常を分ける欄
- 近道で `## 結果` の `- 振り返り:` 行をどう書くか（`tw done` の `reflection` の記録と `reflection_none_ratio` を歪めない形）
- `/loop` での文脈の隔離: 近道が積み上げるメインの文脈の量をどう抑えるか（正典の委譲の実測の段落との整合）

## やること

論点の結論（各1文の理由つき）:
- 印の持ち方: front matter の任意の7行目 `direct: Y`（`loopable` の次。印が無ければ行を書かない。`direct: N` と他の位置は INVALID）、Beads 方式は label `direct:Y`。`tw new --direct`・`tw edit --direct Y|N`（ファイル方式でも受ける）・`tw adopt --direct` で付け外しする。理由: `difficulty`・`loopable` と同じ属性として front matter と label の対応表に並べれば、Beads の `to_task` が label から同じ `Task` の欄に写せ、本文の検査（段の形）に混ぜずに済むため。
- 機械検査の場所: 登録時（`tw new`・`tw adopt`・`tw edit --direct Y`）に条件を外れた印を終了コード2で拒み、着手時に `tw claim` が条件と「登録時の計画が古くない（`registered`）」を測り直して `CLAIMED` の行末に `direct=Y` か `direct=N:<理由>` を出す（印が無ければ出さない）。登録のあとに `tw edit` で `## やること`・`difficulty`（Beads）を変えて条件を外れたら、書き込みは通して印を外し、`EDITED` の次に `DIRECT_OFF\tT-xxx\t<理由>` を出す。理由: 書き直しの委譲を印で拒むと通常の道が詰まり、ファイル方式の `difficulty` は手で直せるので、最後の判定は着手時の1か所に置くのが確実なため。
- しきい値: `difficulty` が `haiku`・段がちょうど1つ・`### 名指すファイル` が2つ以下・`### 作業先` が無い。差分の行数は測らず、直しが名指すファイルの外へ広がるか判断が要ると分かったらメインが近道を降りて通常の委譲に戻る（flow には `lap delegate` が残るので通常として数える）。理由: 差分の大きさは直したあとでしか測れず、事前に測れる名指すファイルの数で近道の大きさを抑えれば、着手後の判断を1つ増やさずに済むため。
- flow での見分け方: T-043 の `tw lap` に段 `direct`（メインが直し始めた）を足す。`tw metrics --stages` は `STAGE` の行の `difficulty` の次に道の列（`direct`＝`lap direct` があり `lap delegate` が無い／`normal`）を足し、段「直し」を計画の次に置く。理由: `claim` の欄より、実際にその道を通ったかを記録する `lap` のほうが近道を降りた回を正しく通常に数えられるため。
- `- 振り返り:` 行: 近道は `- 振り返り: 近道（省いた）` と書き、`tw done` の `reflection` は `skipped` にし、`reflection_none_ratio` の分母から除く（`tw prune` の `reviewed` 判定は行の有無のままで通る）。理由: 振り返っていない回を「兆候なし」に数えると比率が上がって見えるため。
- `/loop` の文脈: 近道でメインが読むのは `tw show` と名指すファイル（2つ以下）と `tw verify` の出力の末尾だけにし、検証のログ全文・正典・`retrospect` は読まない。上限は今までどおり続行判断の `context_size.py` に任せる。理由: 正典の実測（委譲で約7,000文字）と比べて、名指すファイル2つと1段の直しは同じ桁に収まるため。

### 1. 印と機械検査を `tw` に足す
- `skills/task-workflow/scripts/taskfile.py`: `Task` の末尾に `direct: str = "N"` を足し、`parse` が `loopable` の次の任意の `direct: Y` 行を読み（`direct: N`・ほかの値・ほかの位置は INVALID）、`render` が `Y` のときだけその行を書く。定数 `DIRECT_DIFFICULTY = "haiku"`・`DIRECT_MAX_STEPS = 1`・`DIRECT_MAX_PLAN_FILES = 2` を置き、`direct_refusal(task) -> str | None`（`difficulty`・段の数・名指すファイルの数・`### 作業先` の有無で外れた理由）を足す。
- `skills/task-workflow/scripts/task.py`: `p_new`・`p_edit`・`p_adopt` に `--direct`（`new`・`adopt` は真偽、`edit` は `Y|N`）を足す。`cmd_new`・`cmd_beads_new`・`cmd_beads_adopt` は `direct_refusal` で外れたら終了コード2。ファイル方式の `cmd_edit` は `--direct` を受け（`--body-file` なしでもよい）、`Y` で外れたら終了コード2、本文の書き換えで外れたら印を外して `DIRECT_OFF` を出す。Task の写し（`cmd_edit`・`cmd_done` の `taskfile.Task(...)`）は `dataclasses.replace` にして印を落とさない。`cmd_claim`・`cmd_beads_claim` は `_claim_branch_out` に `direct=Y`／`direct=N:<理由>` の列を足す（`registered` でなければ `direct=N:計画が古い`）。
- `skills/task-workflow/scripts/beads.py`: `DIRECT_LABEL = "direct:"` を足し、`to_task` が label `direct:Y` を `Task.direct` に写す（`Y` 以外・2つ以上は INVALID）。`cmd_beads_edit` は `--direct` で label を付け外しし、`--difficulty`・本文の書き換えで外れたら label を外して `DIRECT_OFF`。docstring の対応表に1行足す。
- 自己テスト: `skills/task-workflow/scripts/selftest_task.py` に、`new --direct` が haiku・1段・名指す2つで通り front matter に `direct: Y` が出る／sonnet・2段・名指す3つ・作業先ありを終了コード2で拒む／`edit --direct Y|N`・本文の書き換えでの `DIRECT_OFF`／`claim` の `direct=Y`・`direct=N:` と、`taskfile` の読み取り（`direct: N`・位置違いが INVALID）。`skills/task-workflow/scripts/selftest_beads.py` に `new --direct` の label・拒否・`edit --direct`・`claim` の列。
- 満たす完了条件: 1行目（登録時の印と拒否。両方式）。
