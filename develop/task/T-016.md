## 目的

見出しの行の形を見ずに前方一致・部分一致で判定している検査2件を直す。どちらも
**書いたものが黙って無かったことになる**ため、書き手が気付けない。

- `skills/task-workflow/scripts/init.py` の `check_direction` が、節から出たと判断するのを
  **`## ` で始まる行だけ**にする（`###` 以下は節の中の小見出しとして数える）
- `skills/task-workflow/scripts/taskfile.py:148` の禁止節の判定が、本文のどこかに文字列が
  含まれるかではなく**見出しの行として現れるか**を見る（`^## 結果$` 相当）。
  本文の説明文で節名を `` ` `` で囲んで言及しても通る
- `skills/task-workflow/scripts/selftest.py` に「`###` の小見出しを含むドラフトが `PENDING` に
  なる」ケース、`selftest_task.py` に「本文で禁止節の名前に言及しただけなら `task new` が通り、
  見出しとして書いたら終了コード2で落ちる」ケースがそれぞれ1本ある
- `./check.sh` が通る

3. `selftest.py` に新しいテストケース追加：

## 背景

`skills/task-workflow/scripts/init.py:89` の `check_direction` は行を上から見て、
`## ユーザーから` で `current="user"`、`## エージェントのドラフト` で `current="draft"` に切り替え、
`elif l.startswith("#"): current = None` で節から出たと判断する。この条件が `#` の前方一致なので
**`###` でも `current` が `None` になり、以降の本文を1行も数えない**。

実際に踏んだ: 2026-09-26 に `## エージェントのドラフト` の下へ `### 開発フローとスキルの汎用化` の
見出しつきで89行のドラフトを書いたところ、`init.py` が `PENDING` ではなく
`OK: 未対応の指示は無い` を返した。見出しを太字の1行に変えたら `PENDING: …エージェントのドラフト89行`
になった。

節見出しが1つも無い古いファイルを全体として数える後方互換の分岐（同関数の前半）は変えない。

もう1件は `skills/task-workflow/scripts/taskfile.py:143` の `validate_new_body`。
`FORBIDDEN_NEW_SECTIONS = ("## やること", "## 結果")` を `if s in body` の部分一致で見ているため、
**本文の説明文で節名に言及しただけでも登録が拒まれる**。2026-09-26 にこのタスク群を登録した際、
T-022 の完了条件に「打った出力がタスクファイルの `(結果の節)` に貼られている」と書いたところ
終了コード2の `本文に登録時にはまだ書けない節がある（着手直後に書く節）: ## 結果` で落ち、
言い回しを変えて回避した。必須節の判定（`:145` の `REQUIRED_NEW_SECTIONS`）も同じ部分一致だが、
そちらは緩い方向に外れるだけなので、直すかどうかは揃えて決める。

## 結果

- `init.py` の `check_direction` が節から出たと判断するのを `## ` で始まる行だけにした（`###` の小見出しがドラフトの本文として数えられるようになり、`PENDING` の取りこぼしが直った）
- `taskfile.py` の禁止節の判定を行単位の一致にした（行末の空白は落として比べる）。本文の説明文で `## 結果` に言及しても `task new` が通り、見出しとして書いたときだけ終了コード2で落ちる
- `REQUIRED_NEW_SECTIONS` 側の部分一致は**そのまま**（緩い方向に外れるだけで、厳しくすると `## 背景（…）` のような見出しを新たに拒むため。背景の「揃えて決める」への答え）
