## 目的・背景
T-043 で flow に段の頭（`lap` の `delegate`・`accept`・`review`・`retro`）が残るようになる。これを集計して、(1) `retrospect` の週ごとの振り返りが遅い段から改善のドラフトを積み、(2) `/plan-tasks` が速さを狙う項目を書くとき、推測ではなくこの記録から遅い段を引いて前提にする（利用者の指示。git を疑って実は bd が遅かった GH-218 の空振りを繰り返さない）。

いま: `skills/task-workflow/scripts/metrics.py` の `_column` は送り出しの件数・着手から送り出しまで（`lead_*`）・`verify` の回数などを出すが、段ごとの時間は出さない。`skills/retrospect/scripts/weekly.py` は `tw metrics` と同じ数を `===== 流れの数 =====` に出し、`skills/retrospect/SKILL.md` の「週ごとに振り返る」は観点を「流れの数」「規則の棚卸し」の2つで持つ。`skills/plan-tasks/SKILL.md` の手順2は、速さを狙う項目を「実際に走らせて段ごとの内訳」を測るとだけ書く。

## 決まっていること（蒸し返さない）
- 段の所要時間は「その出来事から、同じタスクの次の出来事までの差」（T-043 で決めた読み方）。段の名前は出来事から決める: `claim`→計画（最初の `delegate` か `step` まで）、`delegate`・`step`→段ごとの委譲、`verify`→検証（記録された所要秒をそのまま使う）、`accept`→受け入れ、`review`→レビュー、`retro`→振り返り、`done`→送り出し（`ship` まで）
- 集計は `difficulty` ごとに分ける（重さの違うタスクを混ぜると遅い段が見えない）

## やること

### 1. 段ごとの集計を足す
`skills/task-workflow/scripts/metrics.py` に、送り出したタスク（期間内の `SHIPPED` の `ship`）ごとに出来事を時刻順に並べて段に割り、段×`difficulty` ごとに件数・中央値・最大（秒）を出す関数を足す。`skills/task-workflow/scripts/task.py` の `metrics` に `--stages` を足して、`STAGE\t<段>\t<difficulty>\t<件数>\t<中央値秒>\t<最大秒>` の行で出す（期間は `--days` と同じ。前の期間との比較は付けない）。`--stages` 無しの出力は変えない。`skills/task-workflow/scripts/selftest_task.py` の `test_flow_records_and_metrics` の近くに、`lap` 入りの flow から段が割れることの自己テストを足す。
### 2. 正典に書く
`skills/task-workflow/WORKFLOW.md` の「`tw` コマンドの参照」の `metrics` の行に `--stages` の出力を足す。T-043 で `metrics` の行の出来事の並びに `lap` は載ったので、足すのは `--stages` の引数と `STAGE` の行の説明だけ。`lap` の行（T-043）が述べる「段の所要時間は、その出来事から同じタスクの次の出来事までの差」と食い違わないようにする。
### 3. 週ごとの振り返りに入れる
`skills/retrospect/scripts/weekly.py` に `===== 段の所要時間 =====` の節を足し、`tw metrics --stages` と同じ行を出す（材料が無ければ `EMPTY`）。docstring の節の説明も足す。`skills/retrospect/SKILL.md` の「週ごとに振り返る」の手順2の表に観点「段の所要時間」の行を足す（材料の行: `STAGE`。当たりの目安: 1つの段の中央値が同じ `difficulty` の着手から送り出しまでの半分以上、または前の記録より目立って伸びた段がある。出し先: その段を縮める手——検証を絞る・委譲しない近道の基準を見直す、など）。手順4の記録の `- 材料:` の行に段の所要時間の有無を足す。`skills/retrospect/scripts/selftest.py` に節が出ることの自己テストを足す。
### 4. `/plan-tasks` で記録を先に引く
`skills/plan-tasks/SKILL.md` の手順2の、待ち時間・実行時間を縮める項目の段落に「走らせて測る前に `tw metrics --stages --days 28` を打ち、記録から遅い段を引く。項目が `/next-task` のサイクルの段のことなら、その行を前提にして `### 実測の内訳` に写す（測り方は『flow の記録』）。記録が無い・項目がサイクルの外の処理なら、これまでどおり走らせて測る」を足す。
