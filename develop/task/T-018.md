## 目的

`develop/task/` などの置き場と ID の形が5ファイルに散らばって直書きされているのをやめ、
1箇所を直せば全部追随する状態にする。**設定で変えられるようにはしない**（正典が「置き場は
規約で固定する」と決めているのは正しい）。汎用性の中身は「フォークして1箇所直せば通ること」で足りる。

## 完了条件

- `skills/task-workflow/scripts/layout.py` があり、少なくとも次を定数として持つ:
  `develop/task`・`develop/direction.md` とその2つの節名・`develop/retrospective.md`・
  `docs/history/tasks.md`・タスクIDの正規表現・作業ブランチの接頭辞
- `task.py`・`taskfile.py`・`init.py`・`legacy.py`・`skills/retrospect/scripts/*.py` が
  これらの値を直書きせず `layout.py` から読む
- `scripts/check_repo.py` に「これらのリテラルがスクリプトに直書きされていない」検査が1つあり、
  戻したら落ちる
- `./check.sh` が通る

## 背景

同じ値が別々のファイルに書かれている:

- `develop/task/`: `task.py`（6箇所）・`taskfile.py`（2箇所）・`retrospect/scripts/material.py`（6箇所）・
  `legacy.py`（`TASK_DIR_NAME = "task"`）
- `develop/direction.md` と節名: `init.py:26-30`（`DIRECTION`・`SECTION_USER`・`SECTION_DRAFT`）
- `develop/retrospective.md`: `task.py`（3箇所）・`retrospect/scripts/scan.py`
- `docs/history/tasks.md`: `task.py:77`（採番の下限に `git show` で読む）・`taskfile.py:204`・
  `legacy.py`（`HISTORY_DIR = "docs/history"`）
- `T-\d{3,}`: `taskfile.py:19`（`ID_PATTERN`）・`taskfile.py:186`（`f"T-{number:03d}"`）・
  `task.py:80`・`task.py:567`（`FEATURE_BRANCH`）・`material.py:39,181`・`transcript.py:17`・`scan.py:29`
- `feature/`: `task.py:567`

`retrospect` は別スキルなので `layout.py` を `import` できるかは配置次第（各スキルは
`${CLAUDE_SKILL_DIR}/../<name>/scripts/...` の相対で互いを呼んでいる）。

## 解くべき論点

- `skills/retrospect/scripts/*.py` から `skills/task-workflow/scripts/layout.py` をどう読むか
  （`sys.path` に足す／値を引数で受け取る／retrospect 側にも同じ定数を置いて check_repo.py で
  一致を検査する）。**スキルを1つだけ入れたときに壊れない形**を選ぶ（T-015 と方針を揃える）
- `check_repo.py` の検査を、どのリテラルを対象にどう書くか（`layout.py` 自身は除外する）

## やること

いまのコードで前提を調べ直した結果、5ファイルへの直書きは背景に書かれた通りで、前提は崩れていない
（`task.py`・`taskfile.py`・`legacy.py`・`init.py`・`retrospect/scripts/{material,scan,transcript}.py`
の実測は下の表のとおり。`retrospect` は `task-workflow` と別スキルで、`sys.path` を自分で足さない
限り兄弟ディレクトリの `layout.py` を `import` できない）。

- `skills/task-workflow/scripts/layout.py` を新規に作り、完了条件にある6つを定数として持たせる:
  `TASK_DIR`（`develop/task`）・`DIRECTION_PATH`（`develop/direction.md`）・`SECTION_USER`
  （`## ユーザーから`）・`SECTION_DRAFT`（`## エージェントのドラフト`）・`RETROSPECTIVE_PATH`
  （`develop/retrospective.md`）・`HISTORY_TASKS_PATH`（`docs/history/tasks.md`）・`ID_FRAGMENT`
  ＋そこから作る `ID_PATTERN`/`ID_SEARCH_PATTERN`（正典3.1のタスクID）・`FEATURE_BRANCH_PREFIX`
  （`feature/`）。ついでに `task.py`（`_history_ids_at_base`）と `taskfile.py`（`history_ids`）が
  一字一句同じ正規表現 `^## (T-\d{3,})\b` を別々に持っているのも `HISTORY_HEADING_PATTERN` として
  centralize する（同じ理由で重複している値なので、6つの最低限に加えて一緒に潰す）
- `taskfile.py`: `ID_PATTERN` を `layout.ID_PATTERN` の再エクスポートにし、`history_ids()` の
  正規表現を `layout.HISTORY_HEADING_PATTERN` に差し替える（`taskfile.ID_PATTERN` を直接読んでいる
  `task.py`・`legacy.py` の呼び出し側は変えない）
- `task.py`: `TASK_DIR_NAME = "task"` を削除して `layout.TASK_DIR` を直接使う。
  `docs/history/tasks.md`・`develop/direction.md`・`develop/retrospective.md`・`feature/` の
  直書き（`os.path.join` の分割引数を含む）を洗い出して `layout.*` に差し替える
- `legacy.py`: 重複していた `TASK_DIR_NAME = "task"` を削除し `layout.TASK_DIR` を使う。
  `os.path.join(toplevel, "docs", "history", "tasks.md")`・
  `os.path.join(toplevel, "develop", "direction.md")` を `layout.*` に差し替える
  （`HISTORY_DIR = "docs/history"` は `docs/history/progress.md` 用で完了条件の対象外なので残す）
- `init.py`: `SECTION_USER`/`SECTION_DRAFT`/`DIRECTION` の直書きをやめ、`layout.SECTION_USER`/
  `layout.SECTION_DRAFT` から組み立てる。`direction.md` のファイル名も
  `os.path.basename(layout.DIRECTION_PATH)` から取る
- `retrospect/scripts/{material,scan,transcript}.py`: **論点の1つ目は「`sys.path` に足す」を選ぶ**
  （値を引数で受け取る案は呼び出し元の SKILL.md まで直す範囲が広がる、retrospect 側に複製して
  `check_repo.py` で一致だけ見る案は「直書きせず読む」という完了条件に反する）。
  `selftest.py`/`selftest_task.py` が使っている `HERE = os.path.dirname(...)`; `sys.path.insert`
  の形をそのまま踏襲し、`task-workflow/scripts` への相対パスを足してから `import layout` する。
  `task-workflow` が入っていない環境では `import layout` が `ImportError` で止まる——これは
  retrospect の SKILL.md が手順1で既に `task.py status` を直接叩いて依存している（T-015 未着手の
  現状の姿）のと同じ「環境の故障」の扱いで、1つだけ入れたときに新しく壊れるところは増やさない
- `scripts/check_repo.py` に検査を1つ足す: 上記7ファイルが `import layout` していること、
  `layout.py` にある値と一致する文字列リテラルが（docstring を除く）コード中に直書きされて
  いないこと、`os.path.join` の分割引数（`"develop", "task"` など）でも同じ値が作られていないこと。
  `layout.py` 自身は対象から外す。実際に1箇所ずつ元へ戻して検査が落ちることを確認済み
- `./check.sh` を通す（`task.py`・`taskfile.py`・`legacy.py`・`init.py` の自己テストは値を
  変えていないのでそのまま通る想定。通らなければ実装の見落とし）

## 注意

- **値そのものは1文字も変えない。** これは純粋なリファクタで、`develop/task/` が
  `develop/tasks/` になったりしない。既存の5リポジトリに影響が出たら不具合
- `WORKFLOW.md`「ファイル配置と CLAUDE.md」の「置き場は規約で固定する（設定で変えられない）」は
  **残す**。集約したことで設定できるようになったと読める書き方にしない

## 結果

- `skills/task-workflow/scripts/layout.py` が置き場（`develop/task`・`develop/direction.md` と2節・`develop/retrospective.md`・`docs/history/tasks.md`）とIDの形・`feature/` を1箇所で持ち、`task.py`・`taskfile.py`・`init.py`・`legacy.py`・`retrospect` の3スクリプトが読む（値は1文字も変えていない）
- `retrospect` からは `sys.path` に `task-workflow/scripts` を足して `import layout`（`selftest*.py` と同じ形）。`check_repo.py` の `check_task_workflow_layout` が AST で `import layout` の有無・直書きのリテラル・`os.path.join` の分割引数を見て止める
- 検証コマンド: 202 pass / 0 fail（+0）。受け入れで1箇所を直書きに戻して新しい検査が落ちることも確かめた
- 振り返り: 同じファイルを3回以上直した（ドラフト0件）
