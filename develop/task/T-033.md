## 目的・背景

スキルは task コマンドを `python3 ${CLAUDE_SKILL_DIR}/../task-workflow/scripts/task.py <サブコマンド>` で呼び、
`skills/task-workflow/WORKFLOW.md` の「`task` コマンドの参照」節に「PATH には入れない。変数に入れず、
毎回そのまま打つ」と書いてある。それでも委譲先が `T="python3 …/task.py"` と変数に入れ、zsh が語分割
せずに空振りする事故が2回起きた（9/24 の T-537 では `;` で続けた `git commit` だけが走り `todo` のまま
コミットされた。tsukumo の GH-97 でも再発）。文章での禁止では防げないので、呼び方を1語にして変数に
入れる理由を無くす（振り返りのドラフト `develop/draft/2026-09-29-task-command-variable-guard.md`、
札「黄 道具（5回目）」）。

長いパスの略記を書いている場所: `skills/task-workflow/WORKFLOW.md`・`skills/task-workflow/SKILL.md`・
`skills/next-task/SKILL.md`（委譲の依頼文を含む）・`skills/plan-tasks/SKILL.md`・`skills/list-tasks/SKILL.md`・
`skills/setup-tasks/SKILL.md`・`skills/task-workflow/scripts/task.py`（usage 等）。`install.sh` はいまスキルと
エージェント定義のシンボリックリンクだけを張る。

## 決まっていること（蒸し返さない）

- コマンド名は `tw`（`task` は go-task の Taskfile ランナーと同名でぶつかるため。ユーザーが選んだ）
- WORKFLOW.md の「PATH には入れない」の方針はこのタスクで覆す（ユーザーが承認済み）
- `tw` は `task-workflow/scripts/task.py` を呼ぶだけの薄い入口にする（ロジックを持たない）

## 解くべき論点

- 張る先と張り方: 既定の置き場（`~/.local/bin` など）、`--dest` や `CLAUDE_CONFIG_DIR` との関係、
  シンボリックリンクか小さなシェルスクリプトか、既に別物の `tw` があるときに触らず警告する扱い
  （スキルのリンクで実ディレクトリ・他所を指すリンクを触らないのと同じ流儀）、`task-workflow` を
  絞り込みから外したときの扱い
- `tw` が PATH に無い環境（install.sh を古い版で走らせたまま等）で、スキルが気づける形にするか
  （`/next-task` などの手順0の依存確認に `command -v tw` を足す等）
- `check.sh` で入口と略記の置き換え漏れ（長いパスの残り）を検査するか

## やること

前提の確かめ（いまのコードで）: `install.sh` はスキル（`--dest`→`CLAUDE_CONFIG_DIR`→`$HOME/.claude/skills`）と
エージェント定義のリンクだけを張る。長いパスの略記は `WORKFLOW.md`「`task` コマンドの参照」・`task-workflow/SKILL.md`・
`next-task`・`plan-tasks`・`list-tasks`・`setup-tasks` の SKILL.md（手順0の依存確認は `${CLAUDE_SKILL_DIR}/../task-workflow/scripts/task.py`
の有無）と `task.py` の docstring にある。`task.py` は `#!/usr/bin/env python3` 付きだが実行ビットが無い。シンボリックリンク
経由で起こしても `sys.path[0]` はリンク先のディレクトリになり、兄弟モジュールの import は通る（一時ディレクトリで確かめた）。
`task migrate --dry-run` の案内を出力に持つのは `task.py`（`LEGACY`・`config-doctor` の `legacy`）・`init.py`・
`maintenance-docs/scripts/check_docs.py`、`## 結果` の拒否文は `taskfile.py`。前提は崩れていない。

論点の結論:
- 張る先は `--bin-dir DIR`、無ければ `$HOME/.local/bin`。`--dest`・`CLAUDE_CONFIG_DIR` とは独立（PATH はシェル側の
  もので、スキルの張る先と関係しない）。張り方は `tw` → このリポジトリの `skills/task-workflow/scripts/task.py` への
  シンボリックリンク（`task.py` に実行ビットを立てる。ロジックは持たない）。既存の `tw` が実ファイル・他所を指す
  リンクなら触らず警告し、このリポジトリを指すリンクなら張り替える。絞り込みで `task-workflow` を外したときは
  `tw` に触らない。張る先が PATH に無い・別の `tw` が先に見つかるときは警告する
- スキルは手順0の依存確認を `command -v tw` にし、無ければ `MISSING` と `./install.sh` の打ち直しを案内する
  （`setup-tasks` は `init.py` の有無も見る）
- `check.sh`（`scripts/check_repo.py`）で、スキルの Markdown に長いパスの略記（`task-workflow/scripts/task.py` を
  `python3` で呼ぶ形）と旧い略記 `` `task …` `` が残っていないこと、`task.py` に実行ビットと shebang があることを検査する

1. `install.sh` に `--bin-dir` と `tw` のリンク（衝突時の警告・PATH の警告）を足し、`task.py` に実行ビットを立てる
2. スキルと `WORKFLOW.md` の略記 `task` を `tw` に置き換え、「PATH には入れない」の注意書きを新しい方針に直す。
   手順0を `command -v tw` にする。`task.py` の docstring・`prog`、出力の案内（`tw migrate --dry-run` 等）と
   それを照らす自己テストを合わせる
3. `README.md` の導入手順に `tw` と `--bin-dir` を書く
4. `check_repo.py` に置き換え漏れと入口の検査を足す
5. `HOME`・`CLAUDE_CONFIG_DIR` を一時ディレクトリに向けて `install.sh` を打ち、既定の置き場・`--bin-dir`・
   衝突（実ファイル・他所へのリンク）・絞り込み・PATH の警告を確かめる
6. `task verify` を通す

## 完了条件

- `install.sh` が `tw` を張り、論点の結論どおりの置き場・衝突時の扱いになっている。張る先を一時
  ディレクトリに向けて動きを確かめている（ホームには張らない）
- スキルと WORKFLOW.md の `task` の略記が `tw` に置き換わり、「PATH には入れない」「変数に入れず」の
  注意書きが新しい方針に合わせて直っている。`README.md` の導入手順も合っている
- `./check.sh` が通る
