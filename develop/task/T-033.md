## 目的・背景

スキルは task コマンドを `python3 ${CLAUDE_SKILL_DIR}/../task-workflow/scripts/task.py <サブコマンド>` で呼び、
`skills/task-workflow/WORKFLOW.md` の「`task` コマンドの参照」節に「PATH には入れない。変数に入れず、
毎回そのまま打つ」と書いてある。それでも委譲先が `T="python3 …/task.py"` と変数に入れ、zsh が語分割
せずに空振りする事故が2回起きた（9/24 の T-537 では `;` で続けた `git commit` だけが走り `todo` のまま
コミットされた。tsukumo の GH-97 でも再発）。文章での禁止では防げないので、呼び方を1語にして変数に
入れる理由を無くす（振り返りのドラフト `develop/draft/2026-09-29-task-command-variable-guard.md`、
札「黄 道具（5回目）」）。

長いパスの略記を書いている場所: `skills/task-workflow/WORKFLOW.md`・`skills/task-workflow/SKILL.md`・
`skills/next-task/SKILL.md`（委譲の依頼文を含む）・`skills/plan-tasks/SKILL.md`・`skills/list-tasks/SKILL.md`・
`skills/setup-tasks/SKILL.md`・`skills/task-workflow/scripts/task.py`（usage 等）。`install.sh` はいまスキルと
エージェント定義のシンボリックリンクだけを張る。

## 決まっていること（蒸し返さない）

- コマンド名は `tw`（`task` は go-task の Taskfile ランナーと同名でぶつかるため。ユーザーが選んだ）
- WORKFLOW.md の「PATH には入れない」の方針はこのタスクで覆す（ユーザーが承認済み）
- `tw` は `task-workflow/scripts/task.py` を呼ぶだけの薄い入口にする（ロジックを持たない）

## 解くべき論点

- 張る先と張り方: 既定の置き場（`~/.local/bin` など）、`--dest` や `CLAUDE_CONFIG_DIR` との関係、
  シンボリックリンクか小さなシェルスクリプトか、既に別物の `tw` があるときに触らず警告する扱い
  （スキルのリンクで実ディレクトリ・他所を指すリンクを触らないのと同じ流儀）、`task-workflow` を
  絞り込みから外したときの扱い
- `tw` が PATH に無い環境（install.sh を古い版で走らせたまま等）で、スキルが気づける形にするか
  （`/next-task` などの手順0の依存確認に `command -v tw` を足す等）
- `check.sh` で入口と略記の置き換え漏れ（長いパスの残り）を検査するか
