## 目的・背景
設定ファイル（`AGENTS.md` → `CLAUDE.md`）の「## タスク運用」節が無いとき、または節に `- ブランチ:` 行が無いとき、いまは `既定` に落ちて、`claim` が `feature/T-xxx` を切り、`ship` が主ブランチへ ff マージで送る。利用者はこれを「送らない」に変えたい。設定を書いていないプロジェクトで、主ブランチが黙って進むのを避けるため。

いまのコード:
- `skills/task-workflow/scripts/task.py` の `read_branch_setting` が、`layout.find_config_file` が `None`（節が無い）のときと、`- ブランチ:` 行が無いときの両方で `"既定"` を返す
- `_claim_preflight`・`_claim_branch_out` は `"既定"`・`"作業ブランチを切る"` なら `git checkout -b feature/T-xxx` を打つ
- `cmd_ship`（ファイル方式と、`_beads_ship_hooks` を渡す Beads 方式の両方がここを通る）は、主ブランチの上なら `SHIPPED\t<base>\t(送る段なし)`、作業ブランチなら rebase → 検証 → ff-only で送る
- `skills/task-workflow/WORKFLOW.md`「ファイル配置と設定ファイル」に「どちらにも節が無ければ、これまでと同じ既定（`- ブランチ:` は `既定`、検証コマンドは打たない）に落ちる」とあり、`- ブランチ:` の語彙表は `既定`／`作業ブランチを切る`／`切らない`／それ以外＝`INVALID`
- `skills/next-task/SKILL.md` 手順8の表と `skills/next-task/ship-stopped.md` の表が `ship` の先頭語ごとの扱いを決め、`/loop` の続行判断は `SHIPPED`（か Beads 方式の `NOTHING`）以外なら続行しない

## 決まっていること（蒸し返さない）
- 対象は「節が無いとき」と「節はあるが `- ブランチ:` 行が無いとき」の両方（利用者「(1)で」）
- 「送らない」を明示する語（`送らない` など）は `- ブランチ:` の語彙に**足さない**（利用者「(2)は足さない」）。書かれた値の語彙は今のまま（`既定`／`作業ブランチを切る`／`切らない`／それ以外は `INVALID`）
- 送らないときの振る舞い: `claim` は枝を切らずに印だけ立てる。`ship` は何もせず（主ブランチへ入れない）新しい判定語で止まる。`/next-task` はコミットまでで止め、送っていないと報告する。`/loop` は続行不要として止まる
- 検証コマンドの扱い（節が無ければ打たない）は変えない

## 解くべき論点
- 新しい判定語の名前と終了コード（`ship` の表・WORKFLOW.md の終了コード表に載せる。「いまの状態では進めない」の 4 に入れるか、別にするか）。行の2列目以降に何を出すか（例: 節が無い・行が無いの別）
- `ship` が「何もせず」止まるとき、自分の着手の印・`task-open-claims` の控え・検証の借りをどう扱うか。印を残すと次の `/next-task` が同じタスクを着手中と見るので、主ブランチ（`HEAD`）で `done` になった印だけは消すいまの `release_shipped` の扱いと揃えるかを決める。決めた理由を `## 結果` に書く
- `claim` の主ブランチへの追い付き（`merge --ff-only`）は送らないときも打つか（`切らない` と同じでよいか）
- `read_branch_setting` が「送らない」を表す内部の値をどう返すか（語彙に足さないので、利用者が書ける語と衝突しない形にする）。`init.check_claude_md`・`tw config-doctor` の `claude_md_lines`（行が無いと `MISSING_LINE`）は今のままでよいか
- Beads 方式の `ship`（`_beads_ship_hooks` の `after_send` でのトラッカー・バックアップ）を送らないときにも打つか

## やること
### 1. `tw` の読み取りと claim・ship を変える
`skills/task-workflow/scripts/task.py` の `read_branch_setting` が、節が無いときと `- ブランチ:` 行が無いときに `既定` ではなく「送らない」の内部の値を返すようにする（docstring も直す）。`_claim_preflight` はそれを `INVALID` にせず通し、`_claim_branch_out` は枝を切らずに `CLAIMED ... branch=<いまの枝>` を出す。`cmd_ship` は冒頭（`DIRTY` の判定のあと）で送らないなら、論点で決めた後始末だけをして新しい判定語の行を出して止まる（rebase・検証・ff マージを打たない）。ファイル方式・Beads 方式の両方がこの道を通ることを確かめる
### 2. 自己テストを足す
`skills/task-workflow/scripts/selftest_task.py` に、(a) 節が無い設定、(b) 節はあるが `- ブランチ:` 行が無い設定のそれぞれで、`claim` が `feature/` を切らないこと、`ship` が新しい判定語を返し主ブランチの SHA が変わらないことを確かめる段を足す（`make_repo` の `branch` 引数で行を落とせなければ、引数を足す）。明示の `既定`・`切らない` の既存の段がそのまま通ることも確かめる。Beads 方式でも同じ判定語になることを `skills/task-workflow/scripts/selftest_beads.py` で1段確かめる
### 3. 正典を直す
`skills/task-workflow/WORKFLOW.md` の「ファイル配置と設定ファイル」の「どちらにも節が無ければ…既定に落ちる」の文と、`- ブランチ:` の語彙表の下に、節や行が無いときは送らない（`claim` は枝を切らず、`ship` は新しい判定語で止まる）ことを書く。「`tw` コマンドの参照」の `claim`・`ship` の行と、終了コードの表に新しい判定語を足す
### 4. next-task の表を直す
`skills/next-task/SKILL.md` 手順8の説明と `/loop` の続行判断、`skills/next-task/ship-stopped.md` の表に新しい判定語の行を足す: コミットまでで止まったこと・送っていないこと・「## タスク運用」節に `- ブランチ:` を書けば送れることを報告して終了し、`/loop` は続行しない
