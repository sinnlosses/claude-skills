## 目的・背景
Jira は `PROJ-123` のようなプロジェクトキー付きの ID 体系を取るので、トラッカーが `jira` のときに
Jira のキーをタスクIDとして扱えるようにしたい。その前段として、ID を読むところが Jira のキーの形を
受けられるようにする（課題を実際にキーへ付け替えるのは後段のタスク）。

今は2つの形に固定されている:

- `skills/task-workflow/scripts/layout.py` の `ID_FRAGMENT`（`T-\d{3,}`）・`GH_ID_FRAGMENT`（`GH-\d+`）・
  `ANY_ID_FRAGMENT`・`ANY_ID_PATTERN`・`ID_SEARCH_PATTERN`・`FEATURE_BRANCH_PATTERN`
- `skills/task-workflow/scripts/beads.py` の `BD_ID_PATTERN`（`t-<n>`／`gh-<n>`）と、それを使う
  `to_task_id`・`is_numbered`・`sort_key`・`id_number`
- `skills/task-workflow/scripts/task.py` の `_bd_task_id` の正規表現 `(?i:t|gh)-[0-9a-z.-]+` と
  使い方の文言「T-999・GH-5 の形式でない」、`--deps` の検査（`layout.ANY_ID_PATTERN`）
- `skills/retrospect/scripts/material.py`（`ANY_ID_PATTERN`）・`transcript.py`（`ID_SEARCH_PATTERN`）
- 正典 `skills/task-workflow/WORKFLOW.md` の「Beads 方式」（ID はトラッカーで決まる段落、今の運用との対応の表、
  「Jira の方式との違い」の表）

## 決まっていること（蒸し返さない）
- 広げるのは **Jira のキーの形だけ**。任意の接頭辞を設定で書ける仕組みは作らない
- Jira のキーの形は `[A-Z][A-Z0-9_]+-\d+`（プロジェクトキーは2文字以上・英大文字で始まる）。Beads の中は
  ほかの ID と同じく小文字（`proj-123`）
- ファイル方式（`develop/task/T-xxx.md`・`taskfile.ID_PATTERN`・`docs/history/tasks.md` の見出し）は `T-xxx` のまま変えない
- Jira 方式でローカルに `tw new` した課題（キーが無い）は `T-xxx` のまま。Jira のキーの課題と混在する
- Jira へは今までどおり書かない（取り込みだけ）

## 解くべき論点
- `GH-5` も `[A-Z][A-Z0-9_]+-\d+` に当たる。トラッカーの種類で受ける形を切り替えるか、形は常に全部受けて
  トラッカーの違いは付け替えの側で扱うか
- `sort_key` での Jira のキーの並び（`T-<n>` → `GH-<n>` → Jira のキー → 仮の ID など）

## やること
前提の確認: 上の「今は2つの形に固定」の箇所は実物と一致した（layout.py・beads.py・task.py・material.py・transcript.py・WORKFLOW.md）。

決めた案:
- 論点1: 形は常に全部受ける（トラッカーで切り替えない）。`T-<n>`・`GH-<n>` を先に、Jira のキーを最後に並べる選択肢にして、`layout.JIRA_ID_FRAGMENT = [A-Z][A-Z0-9_]+-\d+` を `ANY_ID_FRAGMENT` に足す。トラッカーごとの違い（付け替え・採番）は T-041 の付け替え側で扱う。理由は、`feature/<ID>` やコミット件名の検索は設定を持たずに動くことと、切り替えの途中は形が混ざるから。`T-12`（2桁）は Jira の形に当たらず、`T-123`・`GH-5` は先に T・GH の枝が取るので読み方は変わらない。
- 論点2: `sort_key` は `T-<n>`（番号順）→ `GH-<n>`（番号順）→ Jira のキー（キー名の順、同じキーなら番号順）→ そのほか（仮の ID）。
- `beads.BD_ID_PATTERN` に小文字の Jira の枝 `([a-z][a-z0-9_]+)-(\d+)` を足す（`t-<n>`・`gh-<n>` の枝が先）。`to_task_id`・`is_numbered` は Jira のキーも数字付きの ID として扱う。`id_number` は `t-<n>` のままで、Jira のキーは採番の候補に数えない。
- `task._bd_task_id` の正規表現に Jira のキーの枝を足し、文言を「T-999・GH-5・PROJ-123 の形式でない」にする。`--deps` の検査は `ANY_ID_PATTERN` の拡張で追随する。`material.py` の INVALID の文言も足す。
- 自己テスト: `selftest_beads.py` の純粋な部分に `PROJ-123`↔`proj-123`・`sort_key`・`T-xxx`/`GH-n` が Jira と読まれないこと・`layout` の各パターンの例を足す。
- 正典 WORKFLOW.md「Beads 方式」の ID の段落・対応表・「Jira の方式との違い」の表を新しい形に合わせる（付け替えはまだ無いので、Jira のキーは「読める」とだけ書き、T-041 で付け替える旨は書かない）。
- 申し送り（T-041）: `beads.is_numbered` が Jira のキーで真になるので、`task adopt` の「番号でなければ振る」が Jira のキーの課題では番号を振らなくなる。付け替えは T-041 で決める。
