## 目的

`maintenance-docs` の確定群（NG）から誤検知を消す。移行を終えたリポジトリほどノイズが出るので、
いまは出力が信用されない。

## 完了条件

- `skills/maintenance-docs/scripts/check_docs.py` の検査5が、新形式では
  `develop/direction.md` と `develop/task/` を期待し、`develop/tasks.json`・`develop/progress.md` は
  **在ったら旧形式の残り**として扱う（`task migrate` を案内する向き）
- このリポジトリで `python3 skills/maintenance-docs/scripts/check_docs.py .` を打つと、
  `「## タスク運用」節はあるが develop/tasks.json が無い`・`同 develop/progress.md が無い` の
  2件が**出なくなる**
- 旧形式のリポジトリ（`develop/tasks.json` がある）では、残りがあることを指摘する（黙らない）
- 言い回しは `task config-doctor` の検査4（`skills/task-workflow/scripts/task.py` の
  `cmd_config_doctor`）と揃える。同じ判定を2つの違う言葉で言わない
- `./check.sh` が通る

## 背景

- `check_docs.py:42` の `DEVELOP_FILES = ("tasks.json", "progress.md", "direction.md")` を、
  `:347` が「節があるなら3つとも在るはず」として1件ずつ NG にしている。`:330` の
  `develop_present` と `:490` の参考出力も同じ定数を使う
- T-022 で `develop/progress.md` を消したため、claude-skills 自身で2件の誤検知が出る状態
  （T-019 の受け入れで既定の出力を見て気づいた。T-019 の変更前からある挙動）
- `cmd_config_doctor` の検査4は同じことを「在ったら旧形式の残り」として扱い、
  `legacy\tFOUND\t<在るファイル>\ttask migrate --dry-run` を出す

## やること

- 実物で確認: `check_docs.py:42` の `DEVELOP_FILES`、`:330`（節が無いときの `develop_present`）、
  `:347`（節はあるが develop/{f} が無い、というNG）、`:490`（`== 参考 対象 ==`）は前提どおり存在した。
  `cmd_config_doctor` の検査4（`task.py:872`〜）も前提どおり
  「`develop/tasks.json`・`develop/progress.md` が在ったら `legacy\tFOUND\t<在るファイル>\ttask migrate --dry-run`」
- `DEVELOP_FILES` の隣に `DEVELOP_LEGACY_FILES = ("tasks.json", "progress.md")` を足す
  （`cmd_config_doctor` 検査4と同じ組）
- 検査5の `if sec:` 内（旧 `:347`）を、個別ファイルの「無い」NGから次の3つに置き換える:
  - `develop/direction.md` が無ければ NG（新形式の目印でもある。`layout.DIRECTION_PATH`）
  - `DEVELOP_LEGACY_FILES` が1つでも在れば、まとめて1件のNGで
    「旧形式の残り。`task migrate --dry-run` で移行を確かめる」と指摘する
    （`tasks.json`・`progress.md` を個別に「無い」と言わない。旧形式の残りが在るときは
    `develop/task/` の在否は問わない＝同じ状況を2つの言葉で言わない）
  - 旧形式の残りが無いときだけ `develop/task/`（ディレクトリ）の在否を見て、無ければ NG
- 節が無いのに develop 系の痕跡がある、という分岐（旧 `:333`）にも `develop/task/` の在否を足す
  （`DEVELOP_FILES` の3つに加えて `task/` も痕跡として数える）
- `:490` の `== 参考 対象 ==` と、設定ファイル探索（`layout.find_config_file`）はそのまま変えない
- 変更後、`python3 skills/maintenance-docs/scripts/check_docs.py .`（このリポジトリ）と、
  読むだけで確かめる旧形式リポジトリ（`develop/tasks.json` があるもの）の両方で検査5の出力を見て、
  完了条件の2件が消えたこと・旧形式では指摘が残ることを確認する
- `./check.sh` を通す

## 注意

- `:490` の `== 参考 対象 ==` は在否を並べるだけなので、判定を変えても表示は残してよい
- 検査5 は設定ファイルの探索（`layout.find_config_file`）も持つ（T-020）。そちらの判定は変えない
