## 目的

ドキュメント系のスキルが `docs/` の下の決まった名前を前提にしているのをやめ、置き場が違う
プロジェクトでも使えるようにする。既定値はいまと同じにして、既存の5リポジトリの挙動は変えない。

## 完了条件

- `skills/maintenance-docs/scripts/check_docs.py` が `--docs-dir`（既定 `docs`）と
  `--index`（既定 `README.md`）を受け、`docs/` と `docs/README.md` の直書きがそれ経由になっている
- `skills/domain-modeling/SKILL.md` に、`CONTEXT.md` と `docs/adr/` について
  「ユーザーが場所を指定したらそれに従う」に相当する1文がある
- 既定値のまま `python3 skills/maintenance-docs/scripts/check_docs.py .` を打った結果が、
  引数を足す前と同じ
- `./check.sh` が通る

## 背景

- `check_docs.py` は `docs/`・索引 `docs/README.md`・`docs/adr/`・`docs/research/`・`docs/history/`・
  `docs/history/maintenance/`・`README.md`・`CLAUDE.md` を合わせて40箇所以上で前提にしている。
  主なもの: `:101` `os.walk(os.path.join(root, "docs"))`、`:116` `for f in ("README.md", "CLAUDE.md")`、
  `:124` `read(os.path.join(root, "docs", "README.md"))`、`:34` `HISTORY_DIR = "history"`、
  `:37` `INDEX_EXEMPT = ("README.md",)`、`:201` `DOCS_PATH` の正規表現
- 引数の口はすでにある: `:250` `root`（既定 `.`）と `:251` `--skills-dir`。同じ形で足せる
- 逃げ道の有無がスキル間でバラついている。`skills/research/SKILL.md:12` と
  `skills/architecture-proposal/SKILL.md:149` には「ユーザーが場所を指定したらそれに従う」があるが、
  **`skills/domain-modeling/SKILL.md` には無い**（`CONTEXT.md` と `docs/adr/` が固定）

## やること

背景の行番号は現状より少しずれていた（ファイルが伸びて `os.walk` は :110、`for f in
("README.md", "CLAUDE.md")` は :125、`docs/README.md` の read は :133、`INDEX_EXEMPT` は
:46、`DOCS_PATH` は :210、`root` は :259、`--skills-dir` は :260）が、指している中身は
背景の記述どおりで前提は崩れていない。

- `skills/maintenance-docs/scripts/check_docs.py` の `main()` に `--docs-dir`（既定
  `docs`）と `--index`（既定 `README.md`）を足す
- `docs_files()`・`targets()`・`index_entries()` に `docs_dir`（と `index_entries()` は
  `index`）を引数で渡すようにし、`os.path.join(root, "docs", ...)` の直書きをやめる
- `main()` 内の `has_index`・`entries`・`indexable`（`INDEX_EXEMPT` は索引ファイル名から
  作る `index_exempt` に差し替え、グローバル定数は削る）と、検査1〜3・検査7（`docs/adr/`・
  `docs/research/`・`docs/architecture-proposal.md`・`docs/history/`）・末尾の参考出力の
  メッセージを `docs_dir`／索引パスの変数経由にする
- `canon_paths()`／`DOCS_PATH` 正規表現（インストール済みスキルの `SKILL.md` が名指しする
  `docs/` の書式を拾う側）は対象のプロジェクトの `--docs-dir` とは別物なので変えない
- `skills/domain-modeling/SKILL.md` の「ファイル構成」節に、`CONTEXT.md`・`docs/adr/` の
  遅延作成の説明に続けて「ユーザーが場所を指定したらそれに従う。」を1文足す
  （`research`・`architecture-proposal` と同じ言い回し）
- 既定値のままの出力が変更前と1バイトも変わらないことを diff で確認する
- `./check.sh` を通す

## 注意

- `docs/history/` を「どの検査の対象にもしない」扱い（`check_docs.py:34` 近くのコメント）は変えない
- `CLAUDE.md` の位置づけは T-020（設定ファイルを `AGENTS.md` → `CLAUDE.md` の順で探す）で動くので、
  このタスクでは `CLAUDE.md` の探索順に手を入れない。`--docs-dir` と `--index` だけにする

## 結果

- `check_docs.py` が `--docs-dir`（既定 `docs`）と `--index`（既定 `README.md`）を受け、`docs/` と索引の直書きが全部それ経由になった。`documentation/INDEX.md` のような置き場のプロジェクトでも10検査がそのまま使える（受け入れで実際に張って誤検知なしを確認）
- 既定値のままの出力が変更前と**1バイトも変わらない**ことを、`HEAD` の版を同じディレクトリに置いて突き合わせて確認した。`domain-modeling/SKILL.md` にも「ユーザーが場所を指定したらそれに従う」を足した
- 受け入れで別件を見つけてドラフトに積んだ: 検査5 の `DEVELOP_FILES` が旧形式の3点セットを期待したままで、移行を終えたリポジトリで `tasks.json`・`progress.md` が無いことを NG にする誤検知（T-019 の変更前からある）
- 検証コマンド: 215 pass / 0 fail（+0）
- 振り返り: 同じファイルを3回以上直した（1ファイル内の差し替え箇所が多いだけで手戻りなし。ドラフト0件）
